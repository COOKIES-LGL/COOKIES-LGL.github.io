# 研发规范

数据准确性优先级最高：展示文案、请求参数、类型以及兜底逻辑都必须与业务语义一致，避免误导用户或引发线上事故。

# 1. 编码规范

# 1.1 布尔值映射与空值

当后端返回的是布尔值，你要把它映射为“生效 / 失效”等文案时，必须显式处理 0 / null / undefined。普通三元表达式 v ? 'A' : 'B' 会把 null \ 0 \ undefined 当作 falsy，这在你的业务里未必等于“失效”，提示用户注意 0 值。

反例：

{
  key: 'isEffective',
  title: 'Quote status',
  width: 120,
  transform: v => (v ? 'Active' : 'Inactive') // null、0、undefined also shows 'Inactive'
}

# 1.2 对象扩展符的字段覆盖风险

在使用对象扩展符合并对象时，需要注意字段覆盖的顺序。后面的属性会覆盖前面的同名属性，这可能导致意外的数据覆盖。

反例：

const handleFormatList = (priceConfigList?: any[], res?: any) => {
  const { systemYardName, effectiveMonth } = res || {};

  const listTemp = priceConfigList?.map((item) => {
    return {
      systemYardName,
      effectiveMonth,
      ...item, // ❌ item如果 item 中有同名字段，会覆盖前面的值
    };
  });
  return listTemp ?? [];
};

问题分析：

  1. 字段覆盖风险：如果后端 API 变更，在 PriceConfigListItem 中添加了 systemYardName 或 effectiveMonth 字段，就会发生字段覆盖，导致从 res 中获取的值被 item 中的值覆盖。

建议：

const handleFormatList = (priceConfigList?: any[], res?: any) => {
  const { systemYardName, effectiveMonth } = res || {};

  const listTemp = priceConfigList?.map((item) => ({
    ...item, //  ✅ 先展开 item
    systemYardName, // 再覆盖，确保 res 的字段优先级更高
    effectiveMonth,
  }));

  return listTemp ?? [];
};

改进后的优势：

  2. 代码更简洁：使用隐式返回，减少冗余代码

扩展符覆盖规则：

// 后面的属性会覆盖前面的同名属性
const result = {
  a: 1,
  b: 2,
  ...{ a: 3, c: 4 }, // a 会被覆盖为 3
};
// result = { a: 3, b: 2, c: 4 }

# 1.3 原生 enum 的默认枚举值风险

当使用 TypeScript 原生 enum 的默认枚举值时,如果在第一个位置添加新枚举值,会导致后续所有枚举值发生变化,造成严重的兼容性问题。

# 错误示例

// ❌ 危险:使用默认枚举值
export enum Status {
  PENDING, // 0
  PROCESSING, // 1
  COMPLETED, // 2
}

// 如果在第一个位置添加新枚举值
export enum Status {
  DRAFT, // 0 (新增)
  PENDING, // 1 (原为 0)
  PROCESSING, // 2 (原为 1)
  COMPLETED, // 3 (原为 2)
}

// 所有依赖 Status.PENDING (值为 0) 的代码都会出错!

# 正确做法

方案 1: 显式指定所有枚举值

// ✅ 推荐:显式指定所有枚举值
export enum Status {
  PENDING = 0,
  PROCESSING = 1,
  COMPLETED = 2,
}

// 添加新枚举值时,在末尾添加
export enum Status {
  PENDING = 0,
  PROCESSING = 1,
  COMPLETED = 2,
  DRAFT = 3, // 新增在末尾
}

# Code Review 检查清单

在 Code Review 时,对于所有 enum 定义,必须检查:

  • [ ] 禁止使用默认枚举值: 所有枚举成员必须显式指定值
  • [ ] 数值枚举: 必须为每个成员指定明确的数字值
  • [ ] 新增枚举值: 必须添加在枚举定义的末尾,避免影响现有值
  • [ ] 向后兼容: 修改现有枚举时,确保不改变已有枚举成员的值
